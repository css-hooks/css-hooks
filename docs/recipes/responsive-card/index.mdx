# Responsive card

A container query applies styles according to the size of a containing element
rather than the viewport. This behavior lets a reusable component adapt to its
available space. For example, the same card can use different layouts in a
narrow sidebar and a wide content area.

Move the slider to resize this example's query container. Below 400px, the card
places its image before the content in a vertical layout. At 400px or wider, it
places them side by side and adds more content padding.

## Query container

`containerType: "inline-size"` makes the wrapper a size query container on its
inline axis, which is width in this writing mode. Descendants can query that
width while the content continues to determine the wrapper's height.

Because the query does not name a container, the browser uses the nearest
ancestor that supports inline-size queries. The card can therefore move between
a sidebar, grid track, or dialog and respond to its local container.

> [!NOTE] The slider only controls the demo. It changes the wrapper's width, and
> the browser reevaluates the container query. React does not choose the card's
> stacked or horizontal layout.

## Container-relative styles

The base styles stack the image and content. At widths of 400px or wider,
`on("@container (min-width: 400px)", ...)` changes the `<article>` element's
flex direction, gives the image a fixed width, and increases the content
padding. Each override only replaces the properties it declares; the rest of the
base card remains unchanged.

A container query measures an ancestor, not the element it styles. The example
therefore keeps the query container outside the card. Setting `containerType` on
the card would not let the card query its own width.

> [!NOTE] To follow a container farther up the tree, an element inside that
> container can use a query to enable an [inherited flag](../../flags/) for the
> component subtree.
